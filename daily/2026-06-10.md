# 2026-06-10 学习笔记

## 今日主题：Day 24 — 灰区引擎 medium/high 路径验证 + 配置调优

**目标**：调整 TEST_POLICY 和 warning 阈值，让 5 级风险分流的 medium 和 high 路径可达，并完成端到端验证。

---

## 改动内容

### 1. 提高 Guard 单笔上限

`permission-policy.ts`：`maxSingleAmount` 从 `0.01 ETH` → `0.1 ETH`

**原因**：原来 Guard 的 `maxSingleAmount` 和 simulation 的 `HIGH_VALUE_THRESHOLD` 都是 0.01 ETH。任何 > 0.01 ETH 的交易在 Guard 层就被硬约束拒绝，永远不会进入 simulation 层触发 high 分类。两层的阈值不应该相等——Guard 定义的是"允许范围"，simulation 定义的是"风险等级"。

### 2. 降低 Paymaster warning 的 gas 阈值

`pre-tx-sim.ts`：paymaster 警告的 gas 阈值从 `0.001 ETH` → `0.000001 ETH`

**原因**：在中低 gas 价格时（如 Sepolia 1-3 gwei），gas 费可能低于 0.001 ETH，导致 paymaster warning 不触发，medium 路径无法进入。降低阈值确保 warning 在无赞助时可靠触发。

### 3. 修复 trivial 优先级 bug

`pre-tx-sim.ts`：`computeRiskLevel` 中 trivial 检查从优先级 6 移到优先级 5（在 medium 之前）

**原因**：零值转账即使有 paymaster warning，也不涉及资金风险。原来的顺序让零值交易被误判为 medium。

## 验证结果

全部 5 级风险分流通过 API 端到端验证：

| 风险等级 | 测试输入 | 结果 |
|---------|---------|------|
| **trivial** | 0 ETH → self | `autoApproved: true`，"风险极低，静默通过" |
| **medium → auto** | 0.003 ETH → self | 灰区引擎判定金额 ≤ 0.005 ETH，自动批准 |
| **medium → escalate** | 0.008 ETH → external | 金额超过灰区阈值 + 非信任地址 → 升级人工确认 |
| **high** | 0.02 ETH → external | `autoApproved: undefined`，强制人工确认 |
| **guard_rejected** | 0.2 ETH → external | 超过 Guard 单笔上限（0.1 ETH），硬约束拒绝 |

### 前端行为对应

- `trivial` / `medium+auto` → 绿色 banner "灰区引擎自动通过" + 1.5s 自动执行
- `medium+escalate` / `high` → 显示 "④ 确认并执行" + "取消" 按钮
- `guard_rejected` → 显示拒绝原因 + "返回" 按钮

## 发现

### low 等级在无 Paymaster 赞助时不可达

当前 Pimlico 测试环境中 Paymaster 始终返回 `paymasterSponsored = false`。每笔非零交易都触发 "无 Paymaster 赞助，需自付 gas" warning → 进入 medium。

这不是逻辑 bug。语义上：有 Paymaster 赞助 = low（用户无 gas 负担），无赞助 = 至少 medium（用户需自付 gas）。在生产环境中，Paymaster 赞助可用时 low 路径自然可达。

### high 的两条子路径

- **大额转账**（value > 0.01 ETH）：已验证 ✅
- **gas 占比过高**（gas > 20% 余额）：当前余额 0.049 ETH，gas ~0.006 ETH（占 12%），未触发。降低余额到 ~0.03 ETH 以下即可触发。
