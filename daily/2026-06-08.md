# 2026-06-08 学习笔记

## 今日主题：Day 22 — AI Security Track 实践：灰区自动决策规则引擎

**目标**：在 Safe Agent Wallet 中实现灰区自动决策——把 medium 风险场景从「全部丢给人工」变成「规则引擎自动判断」。

---

## 完成内容

### 1. 风险分级扩展：3 级 → 5 级

`computeRiskLevel` 重写，新增 `critical` 和 `trivial`：

```
critical — eth_call revert、余额不足 → 直接拒绝
high     — gas > 20% 余额、大额转账（> 0.01 ETH）→ 强制人工
medium   — 有 warning 但非致命 → 灰区引擎判断
low      — 正常交易，无警告 → 自动通过
trivial  — 零值简单转账 → 静默通过
```

### 2. 灰区规则引擎 `grey-zone.ts`

7 条确定性规则（不调 LLM），按优先级匹配：

| 优先级 | 条件 | 决策 |
|--------|------|------|
| 1 | Guard 软约束触发 + 策略要求人工 | escalate |
| 2 | gas 占比高 + 策略要求人工 | escalate |
| 3 | 零值 + 信任地址 | auto_approve |
| 4 | 金额 < 0.005 ETH | auto_approve |
| 5 | 目标在信任列表 | auto_approve |
| 6 | Guard 软约束 | escalate |
| 7 | 金额超阈值 + 无信任信号 | escalate |

### 3. 确认流程改造

- `confirmation.ts` 签名扩展，接收 `ConfirmationContext`（Guard 结果 + 交易信息）
- critical → 自动拒绝，high → 强制人工，medium → 灰区引擎，low → 自动过，trivial → 静默过
- 灰区引擎判断为 `auto_approve` 时，展示理由后自动进入执行

### 4. 前端适配

- `autoApproved: true` 时，1.5s 后自动触发链上执行，跳过确认按钮
- 绿色 banner 展示决策理由（如"金额低于自动审批阈值，自动通过"）
- 5 级风险颜色：critical 红粗、high 橙、medium 黄、low 绿、trivial 灰

---

## 关键洞察

**灰区不是「不确定所以问人」，而是「信息足够所以能自动判断」。**

之前的逻辑：有 warning → medium → 人工确认。现在：medium → 检查金额 + 地址 + Guard 约束组合 → 能自动判断的自动过，信息确实不够的才升级。

这对应了纵深防御的核心思想：每一层都做自己能做的确定性判断，不把责任推给下一层。
