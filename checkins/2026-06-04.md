# 2026-06-04 打卡草稿

> 复制到 WCB Learning 页面提交

**今日学习**：

给 Safe Agent Wallet MVP 加了 Web 前端。用 Next.js (App Router) + React 18 + TypeScript，从零搭建了一个完整的「交易输入 → Safe Guard 校验 → Simulation 报告 → 用户确认 → 链上执行」Web 界面。API 沿用现有 TypeScript 业务模块，前端通过两阶段 POST 请求完成 guard+sim 检查和链上执行。

**核心收获**：

1. **API 设计先于实现**：在 spec 里逐字段定义了请求/响应的 JSON schema（包含 3 个 stage 状态），写代码时照着 spec 翻译，不需要边写边想。

2. **两阶段 API 模式**：Phase 1（autoConfirm=false）只做只读的 guard + simulation，Phase 2（autoConfirm=true）直接执行链上交易。两个阶段不重复计算，前端负责结构化渲染结果。

3. **类型安全不是事后补的**：Review 发现 `Simulation` 类型的成功/失败路径共用字段，但 API 在失败时根本不返回那些字段——类型说了谎。改成 discriminated union（`SimulationSuccess | SimulationFailed`）后，TypeScript 能根据 `success` 值自动窄化类型。

4. **安全约束写在设计文档里**：console.log 只输出地址不输出私钥、500 错误返回通用消息不暴露内部细节、API response 不包含私钥字段——这三条在设计 spec 里就写死了，实现时逐条验证。
