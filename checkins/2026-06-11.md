# 打卡 — 2026-06-11（Day 25）

## 今日学习内容

- **灰区引擎收尾**：验证 `computeRiskLevel` 中 gas 消耗 > 余额 20% → high 的子路径，通过单测覆盖 4 个边界场景
- **优先级验证**：确认 `computeRiskLevel` 中 critical > high > medium 三级优先级关系正确（余额不足先于 gas 占比，gas 占比先于大额转账）

## 核心收获

**验证不一定要端到端跑一遍完整流程。**

昨天用 API 验证了 trivial/medium/high/guard_rejected 四条路径，只剩 gas 占比子路径因为余额不够低无法触发。今天用一个 4 场景的单测脚本直接验证 `computeRiskLevel`，5 分钟搞定。

`computeRiskLevel` 是纯函数——输入 `SimulationReport`，输出 `RiskLevel`。这种函数不需要链上环境、不需要 API key，mock 数据就能完整覆盖。区分「需要端到端验证」和「纯函数单测就够了」是工程判断力的一部分。

另外给 API 加了 `debugBalance` 参数——不是用来"绕过"限制，而是让测试路径可控。生产代码里加调试入口，只要设计得不会误触发，比"改一下测完再改回来"更干净。
