**核心收获**：

1. **Discriminated union 不是银弹**：TypeScript 的类型区分在编译时有效，但 API 返回的 JSON 是运行时数据。后端 `SimulationReport` 没有顶层 `success` 字段（嵌套在 `callSim.success`），前端 discriminated union 匹配失败，组件静默显示"失败"。数据映射应该在 API 层完成，不要假设后端对象和前端类型天然对齐。

2. **ERC-4337 费用模型**：Paymaster 赞助的是 UserOperation gas，不赞助转账金额。Smart Account 余额必须覆盖转账金额自己。把 Paymaster 当「免费转账」是常见误解。

3. **RPC 节点的可靠性差异**：同一个 public RPC（thirdweb），Phase 1 eth_call 成功、Phase 2 sendUserOperation 失败——调用链越长、RPC 调用越多，节点稳定性越重要。换成 publicnode 解决。

4. **完整闭环才是真的**「跑通了」：昨天写代码时以为功能都做好了，今天实际跑才发现类型映射 bug、RPC 网络问题、余额不足——都是代码层面看不出来的。不实际走一遍链上流程，不能算完成。
